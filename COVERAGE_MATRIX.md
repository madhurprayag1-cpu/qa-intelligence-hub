# Coverage Matrix

## Required mapping
Map each requirement/risk to positive, negative, boundary, authorization/security, integration, regression, and relevant UI/API/database scenarios.

| Requirement ID | Risk | Positive | Negative | Boundary | Security | Integration | Regression | Evidence / SHA |
|---|---|---|---|---|---|---|---|---|
| REQ-example | Set per requirement | Test IDs | Test IDs | Test IDs | Test IDs | Test IDs | Test IDs | Run link + commit |

## Gap rules
A blank cell means not mapped, not passed. Mark scenarios not applicable with a reason and reviewer. Prioritize uncovered high-risk requirements before low-risk cosmetic cases.

## Evidence rules
Coverage claims require actual test-to-requirement links and execution evidence. Do not equate catalog capability counts, discovered tests, or test files with executed coverage. Keep historical snapshots clearly labelled.
